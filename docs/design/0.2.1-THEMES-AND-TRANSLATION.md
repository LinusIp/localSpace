# 0.2.1: themes, design system and translation (the technical brief for track B)

Written 25 October 2026. The owner's rulings of 24–25 October, made technical. This is what **track B** builds: the translation system, the design tokens and the three themes, then the plugin kit (a brief of its own later). **Track A** builds 0.2.0 on `release/0.2`, and Core and the agent on `main`.

## 0. How track B works

- **The owner's rules for track B (2026-10-25):**
  - it works only on the translation, the design and the plugin-kit code;
  - **it never runs anything on the owner's laptop**;
  - **it merges through PRs with CI.**

  It runs as a cloud session. CI compiles and tests; the browser walk is the check.
- **Every visible change is behind a switch that's off by default** (track A's switches: `features` in Core's settings, reported to the client in the environment). The switch names are **`themes`** and **`translation`**. CI and the walk run with every switch on and with every switch off.
- **`CLAUDE.md` applies in full:**
  - the asking rule;
  - no new dependency, library or font without the owner's yes;
  - the product layer is built in-house (no UI kit, no CSS framework);
  - every decision goes in `docs/DECISIONS.md` in the same commit as the code;
  - conventional commits;
  - one PR per sub-task.
- **Before every push:**
  - `cargo fmt --all -- --check`;
  - `npm run typecheck`, `npm run lint` and `npm run test` in `web/`, never `npx` tools.
- **No word "Claude" in anything a person sees:** the app, the site, the release notes. Commit trailers and `CLAUDE.md` stay as they are.
- **Questions for the owner** go in the PR description under **Questions**. They're relayed by track A or read by the owner.
- **Never touch:** `release/0.2`, `package.yml`'s publishing path, the catalog's default, or the organisation code's behaviour.

## 1. The translation system

**The goal (the founder, 2026-10-24):** the best possible quality in every language, with no language first. We start with English, Russian and Uzbek because we can check them. **Adding a language must be one file.**

- **Every string a person sees goes through the strings layer** (`web/src/lib/strings.ts`, `useStrings`), in every page and component. Today only 19 keys do, and about 250 strings are hard-coded.
- **One file per language** (`en`, `ru`, `uz`). A test fails when any language misses a key or has an extra one.
- **Core's messages become codes with parameters,** not English sentences: the verdicts, speeds, placements, licences, download and engine messages, and errors. For example `{"code": "verdict.runs_well", "words_per_second": [15, 20]}`. The client words them.
  - The codes are a proto type (`localspace-proto`, generated to TypeScript; never hand-written).
  - Old clients and older stored text keep working.
- **`<html lang>`** follows the language shown.
- **Plurals and numbers:** Russian plurals (1 / 2–4 / 5+), and number and date formats per language through `Intl`. No library.
- **Under the `translation` switch:**
  - off: today's English, with today's 19 translated keys;
  - on: everything translated.
- **The owner reads every Russian and Uzbek string before release,** from a plain list: English, Russian, Uzbek, where it appears.
- **A CI walk** opens every screen with the browser's language set to `ru-RU` and to `uz-UZ`, with the switch on. It fails if it finds a known English-only string.

## 2. Tokens and the three themes

**The owner's ruling (2026-10-24):**
- three themes, **indigo and amber** (the default), **violet and magenta**, and **teal**;
- each in light and dark, plus "Same as Windows";
- one set of tokens with a theme switch;
- every theme passes WCAG AA in light and dark;
- the person's choice is remembered.

The website uses indigo and amber.

- **Tokens** live in `web/packages/ui/src/ui.css` as `--ls-*`, the names the site already copies.
  - **New:**
    - `--ls-accent-fill` and `--ls-on-accent`: buttons and switches use the fill, and text and links use `--ls-accent`;
    - `--ls-ok` and `--ls-ok-soft`, apart from the accent;
    - `--ls-highlight`, `--ls-highlight-fill`, `--ls-highlight-soft` and `--ls-on-highlight`, for the Recommended badge;
    - a focus ring.
  - `--ls-accent-strong` is a **fill** shade (hover), never text.
- **The switch:**
  - `<html data-palette="indigo|violet|teal">` picks the colours;
  - `data-theme="light|dark"` picks the mode, and when it's absent, `prefers-color-scheme` decides;
  - the bare `:root` holds indigo light;
  - every token is defined in every block.
- **Settings → Appearance:** the theme and the mode. They're stored through Core's preferences (`set_preference`, keys `theme` and `mode`), as the language is, so the choice holds after a restart.
- **Every colour comes from a token.** The literals listed in the audit are removed:
  - `rgba(31,157,91,…)`, `#fff` on accents, the logo's `#1C1E20` and the chat page's `#1D7A55`;
  - the avatar colours, `#eedfb3` and the others in `web/src/index.css`.
- **A CI contrast check** over all six sets, failing below AA:
  - text needs 4.5:1;
  - controls and the decorative `faint` need 3:1.

  The pairs are the ones in the JSON's comment below.

## 3. Type, space, components

- **The typeface is Onest** (SIL OFL 1.1), in place of Figtree, for its Cyrillic (the owner's ruling, 2026-10-24).
  - It's bundled with the app, never fetched, and its licence goes in the third-party notices.
  - Before it ships, **check that the Uzbek oʻ and gʻ (U+02BB) render correctly.**
  - Getting the font file is a download, so ask the owner first.
- **Seven sizes:**

  | Size | Use |
  |---|---|
  | 12 | captions and badges |
  | 13 | secondary text |
  | 14 | body and controls |
  | 16 | chat text |
  | 20 | section titles |
  | 24 | page titles |
  | 32 | the greeting |

  - Line height: 1.5 for body, 1.25 for titles.
  - Weights: 400, 500 and 600.
- **Spacing:** 4, 8, 12, 16, 24, 32 and 48.
- **Radius:** 6 for controls, 10 for cards and the composer, 16 for panels, 999 for pills.
- **Two shadows,** with lines instead of shadows in dark mode.
- **One component set** in `web/packages/ui`, retiring the shell's own `.btn`, `.pill` and `.chip` in `web/src/index.css`:
  - Button: primary, secondary, quiet and danger, at 32 and 40 px;
  - Card;
  - Badge: neutral, accent, highlight, ok, warn and danger;
  - Chip: a chip that does something is a button;
  - Notice: one sentence and one action;
  - Toast: confirmations only;
  - Progress, with its label;
  - Input, Textarea and Select at 36 px;
  - the model card.
- **The focus ring:** 2 px of `--ls-accent-fill` with a 2 px offset, on `:focus-visible`, everywhere. `outline: none` goes.

## 4. The screens for preview.4 (in order)

Each screen is behind `themes`.
1. **Model cards** in Settings → Assistant and on the first run:
   - the name, then badges: **Recommended** (highlight), **Fast**, **Best quality**, **Reads pictures**, **Close other programs first**, **Too large**;
   - one line of facts ("15–20 words a second · 3.2 GB"), with Details folded.
   - **The badges come from Core's verdicts** (architecture §1); the client never judges.
2. **Errors as notices,** where the problem is, with one sentence and one button. The technical text goes under "Details". Toasts are only for confirmations.
3. **The empty chat:** three or four examples in the person's language, matched to the model's abilities. A model that reads pictures offers a photo example.
4. **"What your computer can do":**
   - each capability with ✓ or ✗, the reason in plain words, and what hardware would unlock it;
   - the verdicts come from Core's one fit logic (track A provides the API).
5. **Download progress:** "1.2 of 3.2 GB · about 4 min left", Pause/Resume, and a failure's reason with one button.
6. **The chat screen after the owner's mockup:**
   - the rail holds the new-chat button, then the chats;
   - **a model card at the bottom of the rail:** the name, the Recommended badge if so, and "Runs well · about 25 words a second";
   - a **privacy chip** in the title bar ("Private · on this computer");
   - the composer with the model menu and the send button in `accent-fill`;
   - the footnote "What you write stays on this computer".
   - **The speed is in words a second,** as everywhere in the app, never "token/s".
