01 · THE PRIMITIVE

Not features. Harnesses.

A whiteboard, a planning board, a physics sim, the settings screen, the marketplace itself — each is an installed package, and each brings the same three things. A package missing any of them is not agent-usable, and localSpace says so at install rather than at the moment it fails.

surface A UI for the human, compiled to WebAssembly and run with no host imports. It draws; it cannot reach your disk.
tools Typed actions the agent can call, with JSON Schema parameters. Linted at install: a word budget on every summary, at most eight parameters, no unconfirmed write that cannot be undone.
context A text serialization of what is on screen right now, rendered to whatever token budget Core hands it — so the model sees the board, not a scrollback.
deny

Capabilities are default deny. A package that later wants the network re-prompts with a diff of exactly what changed.

local

The marketplace reads from a local bundle — nothing is downloaded to browse it. Organisations curate their own catalog and publish internal tools under their own key.

02 · THE GATE

The agent never touches anything directly.

Every call goes through Core. That is the entire safety story, and it is one code path — the same one localspace call takes from a shell script, so an automation and an agent cannot diverge.

1 · permissionIs this harness allowed to do this at all? Checked against its manifest and the org policy.
2 · schemaParameters validated against the declared JSON Schema before anything runs.
3 · confirmDestructive actions hold at a gate. A harness cannot pre-approve its own confirmations.
4 · commitThe mutation lands in a version DAG with its parent, tool, parameters, document hash and a diff summary.
5 · replyThe model gets one short line back — never the whole document.
undo

Undo, redo, and reject an entire agent run as a single action — every write it made, gone together.

audit

The log is append-only and hash-chained, verifiable, and reopened across restarts.

untrusted

Fetched and retrieved content is wrapped as untrusted, and the loop does not follow instructions inside it. A tool the model was never shown cannot be called.

03 · TOPOLOGY

One binary. Two modes.

localspace runs Core and the client in a single process on your desk. localspace-serve runs the same Core behind an HTTP and WebSocket API for a team. They share the entire protocol, so the personal app and the company server cannot drift apart.

// PERSONAL

A desktop app that weighs nothing

Core and the client each hold to a 50 MB idle budget — the shell, not the workload. It is measured at runtime and printed against the budget, so the number is never aspirational. The client repaints on input, never on a timer.

// TEAM

The same Core, behind a socket

Per-document ACLs are enforced on every read, every tool call and every sync message. Concurrent edits converge through Automerge. A view-only member's writes are rejected server-side, not merely hidden in the UI.

// AIR-GAPPED

Offline as a posture, not a promise

Under air-gapped mode the web tools are not blocked at call time — they are absent from the model's tool set entirely. It cannot ask for what it was never shown.

04 · PLACEMENT

Know what your machine can run before you download 60 GB.

doctor profiles the machine in front of it, then does real arithmetic over a model's tensor map: what stays GPU-resident, which experts get a hot cache, what falls back to RAM, what streams from NVMe, and what that costs per token. The target is a 100B-class MoE running usefully on a single 32 GB card.

honest

The throughput figure is a roofline estimate, not a measurement — bytes that must move per token, over the bandwidth of the path they move over. It is deliberately conservative, and meant to be replaced by a real measurement at install.

bring

No weights are bundled. Point localSpace at any OpenAI-compatible endpoint — llama.cpp, LM Studio, mistral.rs, vLLM, SGLang — and it speaks to all of them.

05 · HONESTLY

What is built, and what is not.

This is a developer preview, and you are the sort of person who checks. So here is the real state of it — the same table that ships in the repository, where it is written to be checkable rather than flattering.

built — backed by a named test partial — works, with a stated limit not built
STATESUBJECT
built The plugin core, end to endA wasm harness installs, its tools reach the agent under a per-turn budget, its surface runs sandboxed in the client, its context provider is called with a real token budget, every write lands as a commit, and undo, redo and whole-run rejection all work.
built Permissions, version DAG, audit, ACLsDefault deny throughout, with capability diffs on any widening. Append-only hash-chained audit. Per-document ACLs enforced on read, tool call and sync message. Untrusted-content handling in the agent loop.
partial Two topologiesDesktop and server share Core and the whole protocol. The browser client bundle is not built yet — the crate targets wasm32 and the browser surface runner returns an explicit error rather than silently doing nothing.
partial MarketplaceLists and installs from an offline bundle, holding any capability widening at an explicit approval, and scores a package against an eval suite. No signing, no HTTP registry index, no organisation review queue.
partial Placement plannerReal arithmetic and a verdict, with reference maps for a 100B+ MoE at Q4 and a 70B dense at FP8. The throughput is a roofline estimate, and no backend consumes the plan yet.
not built Identity, retrieval, model servingNo OIDC, SAML or SCIM — the single largest gap for a real deployment. No ACL-filtered retrieval yet: docs.search returns "not available in this build" rather than an empty result that would read as "nothing matched". Core routes to one external endpoint; there are no supervised inference workers.
not built Entitlements and the admin consoleOffline-verified seat licensing and the organisation admin console are designed, not written.
Every "built" claim above is backed by code you can run and, in most cases, by a named test. cargo test --workspace is the short version; the whiteboard suite installs the real package — logic running as a wasm component under wasmtime — and drives it through Core exactly as the agent does.

We did not build a server we cannot see into.
We built one binary that never needed one.

There is no telemetry to disable, because none was written. The status bar reads No telemetry as a fact about the binary, not as a setting you have to find. The only network call localSpace makes is the one you point it at.
